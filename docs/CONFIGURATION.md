# Cargo Company configuration

Installation creates schema and owned UI metadata; operating configuration is explicit. No default Company, account, party, tariff or job sequence is installed automatically.

## Native ERPNext prerequisites

Create a Company and its chart/fiscal year through ordinary ERPNext setup. Configure Customers, Suppliers, service Items and UOMs. Each Item needs valid Company-specific income/expense accounts and buying/selling cost centers. Expense Cost Types need an expense Item and authorized Supplier; do not use an Item belonging to a different Company.

Cargo Operator is normally combined with native Sales User, Accounts User and Stock User. Cargo Manager is normally combined with the required native manager roles. Set Company User Permissions. These are role compositions, not permission overrides; native ERPNext permissions remain authoritative.

## Cargo catalogs

Create Road (Truck)/Road and Rail (Train)/Rail Transport Modes. Set Locations' Cargo Location Type and Disabled for Cargo fields; Yard is the verified yard classification. Create Service Types using the current behavior labels, transport mode and job category. Bind each FPL Jobs Sequence row to the actual Service Type created in the target site. Never paste an original site's opaque name or a masked evidence alias.

Configure the following source-verified relative service order. Gate In/Out, Cross-Stuff and Shifting are additional supported behaviors invoked by their corresponding processes; do not invent sequence positions for them.

| Profile | Service order |
| --- | --- |
| Rail/Domestic | Empty Pickup → First Mile → Middle Mile → Last Mile → Empty Return |
| Rail/Export | Empty Pickup → First Mile → Middle Mile → Last Mile |
| Rail/Import | First Mile → Middle Mile → Last Mile → Empty Return |
| Road/Domestic | Empty Pickup → Long Haul → Short Haul → Empty Return |
| Road/Export | Empty Pickup → Long Haul → Short Haul |
| Road/Import | Long Haul → Short Haul → Empty Return |

A Company-specific catalog is exclusive as a whole. An incomplete Company-specific configuration does not borrow missing rows from another Company or the shared catalog. Sites with the existing blank-Company catalog retain the documented legacy fallback.

Configure FPL Cost Types with job mode, fixed-charge flag, Item, Supplier, Company and applicable movement/station qualifiers. A Rail-freight variable cost is explicitly identified. Configure Rail Freight Cost rows by category, exact received container counts, size-specific rates, applicable mixed-size weight limits and explicit priority when predicates overlap. Avoid duplicate single-size predicates and unintended repeated fixed costs. Synthetic verification prices are not default commercial tariffs.

Create container types and wagon types with verified capacities, categories, sizes and count limits. Some legacy container capacity fields have misleading unit names; confirm their validated operational interpretation before binding real physical masters. Do not import the original anomalous container profile or silently convert historical measurements.

## Documents and naming

The packaged Booking naming pattern is BO-.YYYY.-. Start a new installation with its own native counters; never import another site's counters. Sales Order/Freight/Job references are generated by Cargo controllers, not by manually copying linked identifiers.

Job Status uses native draft/submitted/cancelled state; no extra Booking workflow is required. FPL Jobs is a Freight Order child grid rather than an independent operational queue. First/Middle/Last Mile and other queues are selected by service behavior and current status, so completed demonstrations may disappear from assigned-job queues.

## PDF, QR and optional services

Use a supported native Frappe PDF renderer and configure its executable path if required. Configure the native site hostname for links. Both Cargo invoice formats are installed; the QR format encodes a normal authenticated invoice URL without an access token.

Crypto is off by default; optional dependency installation does not enable it. Real provider/PostgreSQL/SMTP bindings and credentials are environment configuration, never fixtures. Email and unverified integrations remain disabled in verification.

## Independent test data

Operating configuration is entered for the target Company using its own native records.
The explicitly invoked disposable test helpers create synthetic examples only and are
not installation fixtures. See [TESTING.md](TESTING.md); no private expectations file
or source-site records are needed.
